## 1. 第三章应回答的核心问题

第三章可以围绕以下论证链展开：

1. 当前多跳知识图谱问答面临什么问题；
2. 现有方法如何处理这些问题；
3. 现有方法还缺少什么；
4. 本章提出什么方法；
5. 所提方法为什么能够弥补上述不足；
6. 实验是否证明方法有效，以及各组成部分分别发挥了什么作用。

这六个问题可以构成全章的主线，但不能只在引言中逐项回答。第 3.1 节提出问题和研究动机，第 3.2 节给出方法与机制解释，第 3.3 节用对比、消融和分析实验闭合论证，第 3.4 节总结结论及适用边界。

第三章不宜表述为“TransferNet 本身不能输出路径，因此给它增加一个搜索程序”。更合适的研究问题是：

> 节点打分式多跳 KGQA 模型能够预测答案实体，却通常不会直接给出由其逐跳得分引导的少量显式证据路径；如何在不引入大语言模型路径规划成本的条件下，把 TransferNet 的隐式推理结果转化为兼顾答案覆盖、首条质量和证据多样性的显式路径集合？

## 2. 对现有方法与挑战的修正认识

### 2.1 不能再声称“现有 GNN 方法无法给出显式路径”

TransferNet、ReaRev 等模型的原始输出主要是实体或答案节点分数，其端到端预测过程本身不直接输出一条离散路径。但是，不能据此声称“没有研究能够从这些模型中获得显式路径”。GNN-RAG 已经采用 ReaRev 等 GNN 预测候选答案节点，再从问题实体到候选节点提取最短路径，并将路径交给大语言模型。

因此，第三章真正需要对比的是两种路径构造思想：

- **答案节点后处理式路径构造**：先得到候选答案，再用最短路径连接问题实体和候选答案；
- **模型推理信号引导的路径检索**：在路径扩展和筛选过程中利用模型产生的实体、关系或逐跳相关性信号。

本章不能把“能否显示路径”作为唯一创新点，而应重点论证“得到的路径是否与模型判断依据一致，是否具有更高的答案覆盖率和更低的冗余”。

### 2.2 “路径分数累积偏置”不是独立的外部挑战

原有讨论中的第二个挑战——多跳路径概率连乘或负对数累积造成的长度偏置——主要是本章采用路径打分和搜索后产生的技术问题，不是所有现有 KGQA 方法共同面对的任务挑战。因此不宜与“隐式推理缺少显式证据”并列为同层次挑战。

它应放在方法节中，作为“如何把异构、逐跳的模型分数转化为可比较路径分数”的设计问题，说明为何需要数值稳定化、归一化、末端实体分数融合或长度控制。相关公式必须与实际代码一致，并通过对应消融证明其必要性。

### 2.3 路径同质化是相对于普通 Top-K/beam search 的直接问题

普通 beam search 按相关性分数保留 Top-K 路径，容易得到共享相同前缀、关系或答案尾实体的高度相似路径。增加 beam size 可能只是重复检索相近证据，并不必然增加有效信息覆盖。

MMR 的作用应准确表述为：在保持路径相关性的同时，抑制已选路径之间的重复，提升有限路径预算下的关系、边或尾实体覆盖。它解决的是候选路径集合的冗余问题，而不是替代模型的答案推理能力。

## 3. 建议提炼的核心创新点

### 3.1 当前可成立的创新点

在 ReaRev 扩展实验完成前，建议将创新点限定为：

1. **提出模型推理得分引导的显式路径重建方法。** 利用 TransferNet 在多跳传播过程中产生的关系与实体相关性信息，对知识图谱中的候选路径进行逐步扩展和评分，将隐式的答案预测转化为可检查的三元组路径。
2. **提出相关性与多样性联合的路径筛选机制。** 在普通 beam search 生成候选路径的基础上，引入 MMR，对路径质量与路径间冗余进行联合控制，从有限预算中选择覆盖互补关系和答案实体的证据路径。
3. **建立面向显式推理路径的评测体系。** 除答案准确率外，从答案路径命中、Top-1 命中、路径级精确率/召回率/F1，以及边、关系和尾实体多样性等维度评价检索结果。

其中，第 1 点是方法主体，第 2 点是主要算法改进，第 3 点是实验与评价贡献。不要把同一算法中的路径打分、负对数变换和 MMR 拆成三个彼此独立的“重大创新”。

### 3.2 ReaRev 实验有效后可升级的创新点

若同一套路径检索框架在 TransferNet 和 ReaRev 上均取得稳定增益，可以将第 1 点升级为：

> 提出一种适用于节点打分式多跳 KGQA 模型的后置显式路径检索框架，通过统一的模型得分接口将不同模型的隐式节点推理结果转化为显式证据路径。

这时第三章的贡献不再依附于 TransferNet，而是“模型无关的路径检索层”。但“模型无关”仍不宜写得过满，更准确的适用范围是：模型能够输出答案节点分数，并且最好能够导出逐跳节点分数、关系相关性或边权重。

如果 ReaRev 上没有效果，则保留 TransferNet 专用定位；ReaRev 结果可作为适用边界分析，不能据此宣称通用框架。

## 4. 与 GNN-RAG、RoG 和 ToG 的关系

### 4.1 GNN-RAG 是 SP 基线的研究定位来源

GNN-RAG 已证明 GNN 的答案节点可以被转换为显式路径，但其核心路径构造方式是从问题实体到候选答案实体提取最短路径。它回答了“如何给 GNN 候选答案附加路径”，却没有直接证明最短路径就是 GNN 实际依赖的推理证据。

本轮不复现 GNN-RAG 的 ReaRev 骨干，而是在相同 TransferNet 候选答案、图结构、可用跳数和路径预算下，
实现“基于 TransferNet 候选答案的最短路径后处理（SP）”。因此 SP 是当前论文的直接路径构造基线，
不是完整 GNN-RAG 数值复现。

因此，本章与 GNN-RAG 的差异应表述为：

- GNN-RAG 的最短路径主要使用图结构连通性和候选答案终点；
- 本章方法尝试在搜索过程中进一步利用 KGQA 模型的逐跳推理分数；
- 本章还通过 MMR 控制多条路径之间的冗余，而不是仅枚举连接候选答案的最短路径。

“本章路径更可靠”只能作为实验假设，必须由答案覆盖、忠实性代理指标和下游问答效果共同支持，不能仅凭方法直觉下结论。

### 4.2 RoG 和 ToG 主要用于研究定位

RoG、ToG 代表使用大语言模型规划、选择或遍历知识图谱路径的路线。与它们的主要对比角度是：

- 本章复用已有轻量 KGQA 模型的推理信号，不要求为路径检索微调大语言模型；
- 搜索过程可离线缓存模型分数，推理成本和显存需求较低；
- 输出路径直接来自给定知识图谱，结构合法性容易保证；
- 代价是路径质量受上游 KGQA 模型和候选子图召回上限约束，语义规划能力可能弱于大语言模型方法。

论文中应在相关工作和方法定位表中比较 RoG、ToG，但不必在无法统一子图、模型规模和推理预算时强行做数值对比。若后续完成 ReaRev 适配，可再在相同数据、子图和候选节点下做跨骨干比较；它不阻塞当前 TransferNet 闭环。

## 5. 后续 ReaRev 路径检索实验的可行方案

### 5.1 实验目的

该实验不属于本轮执行计划；若后续启动，其目的不是再次证明 ReaRev 能检索候选答案，而是验证以下假设：

> 与只连接 ReaRev 候选答案节点的最短路径相比，使用 ReaRev 内部推理分数进行逐跳搜索，并通过 MMR 选择的路径集合，能够在相同路径预算下获得更好的答案覆盖、模型忠实性和证据多样性。

### 5.2 两档接入方式

#### 强接入：推荐方案

修改 ReaRev 的推理导出逻辑，为每个问题保存：

- 主题实体；
- 候选子图的实体与三元组；
- 最终答案节点概率；
- 每轮或每层 GNN 推理后的节点概率；
- 若实现中可取得，再保存每条指令对应的关系注意力、关系相关性或消息权重。

将这些信息适配为统一 score cache，再复用本项目的候选扩展、路径评分和 MMR 选择。路径第 (h) 跳的得分应优先使用第 (h) 轮节点/关系信号，而不是把最终答案概率机械复制到每一跳。

强接入最能检验本章的核心主张：路径是由模型的逐步推理信号引导出来的。

#### 弱接入：保底方案

如果 ReaRev 只能稳定导出最终候选答案节点及其概率，可先：

1. 在同一候选子图中枚举主题实体到 Top-K 答案节点的有界路径；
2. 用答案节点概率作为终点相关性；
3. 使用 MMR 从候选路径中选择互补路径。

弱接入可以验证 MMR 是否优于直接枚举最短路径，但不足以证明“逐跳模型推理得分引导”。论文必须把这两种结论区分开。

### 5.3 建议的对照组

在完全相同的 ReaRev checkpoint、测试集、候选子图、答案候选数量、最大跳数和最终路径条数 (K) 下比较：

| 组别 | 候选路径/评分方式 | 目的 |
|---|---|---|
| ReaRev | 直接使用答案节点预测，不输出路径 | 核对原模型答案性能 |
| SP | 到 ReaRev Top-K 候选答案的最短路径 | 复现 GNN-RAG 式路径构造基线 |
| Score-Beam | 使用模型分数的普通 beam search，MMR 系数为 0 | 验证模型得分引导的作用 |
| Score-MMR | 使用相同模型分数的 beam search + MMR | 验证多样性选择的增益 |
| 可选：SP-MMR | 最短路径候选 + MMR | 分离“候选生成方式”和“多样性选择”的作用 |

建议先在 WebQSP 上跑通，因为 ReaRev、GNN-RAG 与本项目均覆盖该数据集；之后扩展到 CWQ。MetaQA 可以作为规则性较强、跳数清晰的数据集验证跨数据集稳定性。

### 5.4 评价指标

#### 路径有效性

- Answer-path Hit@K：检索路径终点是否包含真实答案；
- Top-1 answer-path hit：最高排名路径是否到达真实答案；
- 基于路径终点答案集合的 Precision、Recall、F1；
- 空路径率、平均路径数和平均路径长度。

#### 路径多样性

- 边 Jaccard 多样性；
- 关系序列多样性；
- 尾实体覆盖率；
- 关系覆盖率；
- 共享前缀比例或重复路径率。

#### 模型忠实性

WebQSP/CWQ 通常没有完备的黄金推理路径，仅以“路径终点命中答案”不能证明路径忠实。建议至少增加以下代理实验之一：

- **充分性**：仅保留检索路径构成的子图，重新运行 ReaRev，观察答案分数或 Hit@1/F1 的保留程度；
- **必要性**：从原候选子图中删除检索路径包含的边，再运行 ReaRev，观察原预测答案分数下降幅度；
- **对照删除**：与删除相同数量的随机边、最短路径边进行比较。

若 Score-MMR 路径构成的小子图更能保留原预测，而删除这些路径又造成更大性能下降，才能更有根据地称其“更符合模型推理依据”。

#### 可选下游效果

将 SP、Score-Beam 和 Score-MMR 的相同数量路径分别输入同一个固定 LLM，比较答案 Hit@1、Macro-F1 或 Exact Match。此实验可说明路径对后续 RAG 的价值，但不是第三章成立的必要条件，也不要混入第四章的微调贡献。

### 5.5 超参数与公平性控制

- 固定 ReaRev 候选子图，避免把子图召回差异误认为路径算法增益；
- 所有方法固定最大跳数、候选答案数、最终路径预算 (K)；
- beam size 和 MMR 系数只在验证集选择，测试集只报告一次；
- 同时报告 λ=0 的普通 beam 与 λ>0 的 MMR，避免只证明“增大候选数量有效”；
- 分 1-hop、2-hop、3-hop 和多实体问题报告结果；
- 报告运行时间、峰值显存和是否需要 LLM/LLM 微调，以支撑“代价较低”的论述；
- 对主要指标进行配对显著性检验或 bootstrap 置信区间，不能只比较小数点后的单次差异。

### 5.6 判定标准与论文措辞

满足以下现象时，ReaRev 实验才足以支撑跨模型贡献：

1. Score-Beam 相对 SP 在答案路径召回或忠实性上有稳定提升；
2. Score-MMR 相对 Score-Beam 在相同 (K) 下提升多样性，并且不显著损害答案覆盖；
3. 至少在 WebQSP 全量测试集上成立，最好在 CWQ 或 MetaQA 上复现；
4. 增益不是由更大的候选集合、更多路径或不同子图造成。

若只有第 2 条成立，应将贡献限定为“MMR 路径去冗余”；若只有答案覆盖提升但忠实性实验不成立，应使用“有效性更高”，不要使用“更忠实”或“更可解释”。

## 7. 后续跨骨干时的算法名称建议

当前名称如果仅突出 MMR，会弱化“模型推理分数引导”这一更核心的部分。建议暂用中文名称：

> **模型推理得分引导的多样化路径检索方法**

英文候选名称：

> **Reasoning-Score-guided Diversified Path Retrieval（RSDPR）**

这个名称包含三个必要信息：上游推理得分、路径检索、多样化选择，同时不绑定 TransferNet，也不声称输出严格因果解释。

另一个更短的候选名称是：

> **Score-guided MMR Path Retrieval（SMPR）**

建议在 ReaRev 实验完成前不要最终定名。如果强接入成功，优先使用 RSDPR；如果只能完成最终答案分数的弱接入，使用 SMPR 更准确。现有工程中的 AP-MMR 可以暂时保留为实现名，论文重写时再统一替换，避免在实验未定型前大范围改代码和图表。

## 8. 后续 ReaRev 扩展执行顺序

1. 获取并复现 GNN-RAG 使用的 ReaRev checkpoint、数据预处理和答案节点输出；
2. 用其官方最短路径逻辑建立 SP 基线，核对路径数量和答案覆盖；
3. 检查 ReaRev 前向过程可导出的逐层节点概率、关系指令或消息权重，确定强接入字段；
4. 编写 ReaRev score adapter，接入现有统一检索内核；
5. 先在 WebQSP 小样本上检查路径合法性和分数范围，再跑验证集选参；
6. 在全量测试集完成 SP、Score-Beam、Score-MMR 对比及消融；
7. 增加充分性/必要性实验，决定论文能否使用“忠实性”表述；
8. 根据结果最终确定算法名称、创新点层级和第三章标题；
9. 按 3.1—3.4 的结构重写第三章正文。

## 9. 后续扩展的结论边界

ReaRev 扩展可以增强跨骨干证据，但不是当前第三章创新强度的前提。实验重点不能写成“我们也能从 ReaRev 找到路径”，因为 GNN-RAG 已经通过候选答案节点和最短路径完成了这一点。真正有价值的后续检验是：本章方法是否能利用 ReaRev 的内部推理分数，检索出比最短路径后处理更有效、更少冗余，并且更符合模型预测依据的路径集合。

在该实验完成前，论文应明确限定为“TransferNet 上验证的路径检索方法”；只有跨骨干比较和相应边界验证成立后，才讨论将其升级为节点打分式 KGQA 模型的显式路径检索框架。

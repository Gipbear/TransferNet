# 第五章 基于知识图谱增强大语言模型的多跳问答系统

第三章提出了基于答案后验融合的 MMR 多跳路径检索算法，第四章提出了基于事实信息增强的 QLoRA 监督微调方法，分别给出了"路径检索器"与"忠实推理器"两项核心能力。然而，将上述两项能力简单串联为"一次性把候选路径输入微调模型、解码得到答案与引用"的单次直答范式时，仍存在三个工程级缺陷：候选路径的噪声并发暴露、模型自报引用缺乏闭环验证、计算无早停机制。本章提出一种基于分层服务架构与决策层 Agent 的完整问答系统，在保留 Ch3/Ch4 算法贡献的同时，通过批式渐进推理与引用路径自核查机制系统性地解决以上三个缺陷。

## 5.1 引言

设候选路径集为 $\mathcal{P}_B = \{P_1, \ldots, P_B\}$，单次直答范式将候选路径与问题一次性输入微调模型 $f_\theta$，得到答案集合与引用路径子集。该范式存在三个相互独立的局限：

1. **噪声并发暴露 (L1)**：MMR 多样性策略保证了候选路径的覆盖广度，但同时意味着干扰路径与支持路径并发进入上下文。在 $B$ 较大时（如 $B=50$），模型注意力被稀释，对支持路径的辨别能力下降。

2. **引用闭环缺失 (L2)**：第四章微调使模型具备显式输出引用路径编号的能力，然而该引用的真伪仍由生成模型自报，无独立验证机制；当引用错误时，错误难以被检测与纠正。

3. **计算无早停 (L3)**：单次直答必须消耗全部 $B$ 条路径的上下文长度，即使前若干条路径已足够定位答案；这造成显存与时间的浪费，且加剧了 (L1) 的噪声暴露。

本章的设计目标是在不修改 Ch3 检索算法与 Ch4 微调模型的前提下，通过**分层服务架构**与**决策层 Agent** 同时解决以上三者，使整个问答系统具备引用可验证、计算可早停、模块可替换的工程属性。

## 5.2 系统总体架构

本章系统由三层模块组成：底层检索服务层（基于 Ch3）、中层推理服务层（基于 Ch4）、上层决策层 Agent（本章核心创新）。三层之间通过 HTTP 协议化接口通信，模块解耦、可独立部署与替换。系统总体架构如图 5-1 所示。

### 5.2.1 分层架构设计原则

系统采用以下三个设计原则：

**(1) 常驻服务化。** 检索模型 TransferNet 与推理模型 LLaMA-3.1-8B + LoRA Adapter 在系统启动时一次性加载到 GPU 显存并以 HTTP 服务形式常驻，避免每次问答请求重启 GPU 进程的高额开销（约 3-4 分钟模型加载时间）。这使得单条问答请求的端到端延迟可压缩至秒级。

**(2) 协议化工具。** 决策层 Agent 仅依赖 JSON 格式的接口契约，不耦合底层模型的具体实现：检索服务暴露 `(question, topic_mid, beam_size, lambda_val) → ranked paths` 接口，推理服务暴露 `AnswerWithPaths` 与 `CitedPathCheck` 两个工具协议。在不改动决策层逻辑的前提下，可替换底层为其他 KGQA 检索算法或更大的 LLM 底座。

**(3) 共享底座。** `AnswerWithPaths` 与 `CitedPathCheck` 复用同一份基座 + LoRA Adapter，仅通过提示词模板切换工具语义。这避免了为不同任务加载多份模型实例的显存开销。

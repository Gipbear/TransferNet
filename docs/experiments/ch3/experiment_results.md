## 0.1 填表规则

1. 本地实验的每一行结果必须能够追溯到配置文件、结果目录或运行清单。
2. 引自论文的结果必须记录论文名称、表格编号或页码；不能只填写一个无法核对的数字。
3. 本地复现结果标记为“复现”，原论文报告结果标记为“论文”，二者不能混写。
4. 所有百分比统一使用 \(0\sim100\) 的百分数，保留两位小数；原论文只报告一位小数时保留
   原精度，不自行补零制造额外精度。
5. 不适用的单元格填写“—”，尚未获得的结果填写“待补”，实验失败填写“失败”，不能留空。
6. 每张表都填写实际样本数 \(N\)，避免把冒烟结果误写成全量结果。
7. `Hit@K`必须在表头写明具体的 \(K\)，不能只写“Hit”。
8. 所有最优值和次优值应在同一张表完成后统一加粗或下划线，填写过程中不要提前标记。
9. 不同方法使用不同知识图谱版本、问题子图、实体链接或LLM时，在“可比性说明”中如实记录。
10. 没有标准推理路径标注时，只使用“答案路径命中”“答案覆盖”和“关系多样性”等表述，
    不将路径尾实体正确直接表述为“路径完全正确”或“模型忠实”。
11. 如果参数使用测试集选择，必须标记为“诊断性结果”；只有验证集选参后一次性运行的测试集
    结果才能标记为“正式测试结果”。
12. 结论栏不仅记录是否提升，还要记录代价、例外数据集和可能原因。

### 1.2 核心结论看板

这里只填写一句话结论，详细分析放在对应章节。

| 结论编号 | 需要验证的主张 | 当前结论 | 证据表格 | 支持程度 |
|---|---|---|---|---|
| C1 | 模型推理得分引导优于候选答案最短路径后处理 | 全局归一化后，普通得分束搜索在 PathHit@20、PathHit@1、F1 上均略高于 SP；终点感知与完整方法继续扩大优势，但 SP 的关系多样性更高。 | 表4-1 | 部分支持 |
| C2 | 模型推理得分引导能够改善首条路径或答案覆盖 | 加入终点实体融合后，PathHit@20、PathHit@1、F1 均提升；完整方法的 PathHit@20 最高。 | 表4-1、表5-2 | 充分支持 |
| C3 | 关系冗余抑制能够提高固定预算下的路径多样性 | 完整方法相对同终点感知、无冗余抑制对照，关系多样性提高 7.06 个百分点，PathHit@20 提高 1.52 个百分点。 | 表4-1、表5-1 | 部分支持（F1 下降、PathHit@1 不变） |

| C5 | 所检索路径能够改善固定LLM的下游问答效果 | 六组全量结果中，五种路径上下文均明显优于无路径；完整方法的 QA Hit@1 / Hit_any 最高，但相对固定惩罚和终点感知的 QA Hit@1 配对区间均跨0。 | 表7-1、表9-3 | 充分支持路径上下文收益；不支持自适应的稳定 QA 优势 |

支持程度统一填写：

- **充分支持**：核心指标一致提升，且无明显反例或口径问题；
- **部分支持**：只在部分指标或数据集成立；
- **不支持**：主要指标无提升或结论方向相反；
- **未判断**：实验或统计尚未完成。

### 2.3 最终方法参数

| 参数 | 符号/配置字段 | WebQSP | 选择依据 |
|---|---|---:|---|
| 路径规模 | \(K\) / `beam_size` | 20 | 受控主对照固定；当前实现中 `beam_size=K`，SP 另以 `path_budget=20` 对齐预算 |
| 冗余惩罚系数 | \(\beta\)/`lambda_val` | 0.2 | 全部主对照固定，不使用测试结果重新选参 |
| 终点实体权重 | \(\eta\) | 1.0 | 全部主对照固定 |
| 关系候选阈值 | 共享 `threshold` | 0.01 | 对每跳关系得分执行“分数不少于 0.01”的过滤 |
| 实体候选阈值 | 共享 `threshold` | 0.01 | 对每跳实体得分执行同一“分数不少于 0.01”的过滤；并非独立超参数 |
| 关系得分归一化 | `relation_normalization` | `global` | 先在整跳关系分布上归一化，再对当前路径可达且通过实体过滤的边取值，保证不同路径间分数可比 |

**口径警告（字段名与实际语义不一致，写论文时必须注意）：**

- `relation_coverage` 与 `edge_coverage` 的名称容易被读作“覆盖了问题子图中多少关系/边”，但其**分母是检索路径集合自身的关系数或边数之和，与子图规模无关**。二者实为“不重复率”，取值越高说明这 \(K\) 条路径内部复用的关系/边越少。正文若使用这两个指标，**不得表述为对知识图谱或问题子图的覆盖率**，本文档表列名已相应改为“关系不重复率”“边不重复率”。
- `relation_jaccard_diversity` 使用的 \((\text{跳序},\text{关系})\) 集合与第 3.2.3 节定义的带位置关系相似度一致；`jaccard_diversity` 则细化到具体的头尾实体，两者不是同一量。
- 当某问题检索到的路径少于 2 条时，`compute_path_diversity` 对全部五个指标返回 0（含 `tail_diversity`），这些 0 值计入数据集平均，因此各多样性指标的均值受“单路径问题”比例影响。

- 关系多样性指标的解读边界：\(D_{\mathrm{rel}}\) 只看关系名是否重合，无法区分「指向不同答案的不同关系」与「指向同一答案的平行关系」，因而会被平行边刷高。正文与本文档均不得单独以 \(D_{\mathrm{rel}}\) 高低论证检索质量，须与 \(D_{\mathrm{tail}}\) 及 PathHit/F1 合并观察。
- 当前结果能够支持的论文表述：在同一 WebQSP 子图、固定 20 条路径预算下，完整方法相对 SP 提高路径答案覆盖（PathHit@20 +4.43，CI 不跨0）与召回率（+8.58），路径答案 F1 净提高 3.60，精确率下降 1.01；族内终点感知评分显著提高首条路径质量；自适应关系冗余抑制进一步提高答案覆盖和关系多样性，但存在集合 F1 权衡。**不得使用「首条路径质量优于 SP」的表述。**

**需要回答：**

- 加入关系相似度惩罚是否确实降低路径冗余？是。当前自适应项在同终点感知对照上使关系多样性从 64.73 提高到 71.79。
- 固定惩罚是否损害高相关路径或首条质量？PathHit@1 不变，集合 F1 相对无惩罚下降 0.02 个百分点。
- 自适应惩罚是否取得更好的质量—多样性权衡？若以 PathHit@20、PathHit@1 和关系多样性为主，则相对固定惩罚获得 +0.82、+0.00、+5.45 个百分点；若以集合 F1 为主，则下降 0.50 个百分点。因此结论是“覆盖—关系多样性更优”，而不是全面质量更优。
- 第二个创新点如何表述？可以保留“路径得分自适应的关系冗余抑制”，但必须同时报告 F1 权衡，并将覆盖和关系互补作为主要目标。

**结果分析：**

- F1 报告口径：路径尾实体集合 F1 只用于解释检索覆盖—噪声权衡；无惩罚 / 固定 / 自适应的最终回答集合质量以 QA Macro-F1 主报，并同时保留 Micro-F1 和 EM。
- 路径输入总体是否改善问答：是，五种路径条件均明显优于无路径。
- 路径指标提升是否传递到下游QA：终点实体融合的路径指标提升传递为所有 QA 指标提升，且相对普通得分束搜索的 Hit@1 增益为2.21个百分点（95% CI [0.76, 3.67]）。完整方法的更高路径覆盖进一步提高 Hit@1 和 Hit_any，但未使 Macro-F1、Micro-F1、EM 全部提高。
- 哪种路径检索方式最有利于下游模型：若以单答案命中为主，完整方法最好；若以 Macro-F1、Micro-F1、EM 为主，终点感知得分路径最好。
- 固定与自适应的最终 QA 差异：自适应相对固定的 Macro-F1 / Hit@1 分别为 -0.08 / +0.06 个百分点，但95% CI分别为[-1.05, 0.90] / [-1.08, 1.20]，均跨0；因此没有稳定证据支持自适应改善最终回答质量。
- 多样性提高但QA下降的情况及可能原因：完整方法增加互补证据也增加了上下文内的候选答案和关系模式；固定零样本提示未必能稳定整合额外信息。该解释是推断，需案例分析验证。
- 该结果与第四章路径监督微调的区别：本节固定基座模型、只替换检索上下文，验证路径的即时可利用性；第四章另行改变模型参数与训练数据。

**效率结论：**

- 完整方法相对普通得分束搜索的额外开销：TARRS平均单题时间为58.21ms，对普通得分束搜索为59.17ms；三次完整运行分别为91.82、92.04和92.27秒。该结果未显示自适应重排引入额外总开销，但不据此宣称跨实现的速度优势。
- 与SP的时间差异：TARRS平均时间比SP低10.2%（58.21ms 对64.81ms），且P95更低（214.71ms 对582.95ms）；SP仍具有更低的P50（2.08ms），说明其延迟分布长尾明显，不能只以单一均值概括成本。
- 自适应选择的复杂度是否成为瓶颈：五种得分方法的扩展状态数和候选路径数相同，固定/自适应只改变最终选择；当前 (K=20) 下，自适应重排没有成为端到端检索瓶颈。
- “低额外成本”能够支持到什么程度：可写为“相对普通得分束搜索，TARRS 在相同候选空间与路径预算下未呈现可分辨的额外检索开销，且路径检索阶段不调用 LLM”；不可扩展为跨硬件、跨实现或相对所有外部方法的速度优势。
